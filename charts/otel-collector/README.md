# Collector chart: offline source profile

Disabled by default. Explicit enable emits four namespaced objects: ServiceAccount, ConfigMap, ClusterIP Service and Deployment in `ai-observability`. Config owns the prerequisite namespace/network policy. Fixed `otel-collector` names/selectors match its policy contract; this is a single shared instance, not one instance per workload namespace. `dev`/`qa` are alternative offline profiles and must not be applied together to one cluster.

The chart preserves Collector 0.164.0's existing image digest and capture processors. It adds process-health probes (not pipeline/backend-health acceptance), resource bounds, a tokenless identity, non-root UID 10001, read-only filesystem and restricted capabilities. There are no dependency archives, Namespace/CRD/RBAC/Ingress/PVC/cloud definitions or secret values. Existing local/native sources are unchanged. The immutable image and rendered security settings do not prove runtime UID/PSA compatibility.

Trace export targets the future `jaeger:4317` service in the same namespace with the existing plaintext in-cluster profile; config policy limits this edge. Jaeger is not deployed by this chart. Config C and a separately reviewed Jaeger/backend profile are prerequisites before any functional rollout. OTLP is reachable only through internal ports and the planned config network policy; no external gateway endpoint is enabled. Metrics are not exposed by a public service. APIM remains outside AKS and Terraform-owned.

`python scripts/check_collector_chart.py --restore` performs locked-tool lint/renders, negative schema checks and source-policy checks. CI separately validates the generated Collector config in the existing digest-pinned distribution. No Helm install, Kubernetes access, live backend test, registry publication or Azure operation is performed. Actual Kubernetes admission, image startup, network enforcement, TLS/identity decisions and backend ingestion remain later checks. This source slice is not deployable authorization.
